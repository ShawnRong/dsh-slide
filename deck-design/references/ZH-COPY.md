# 中文文案标准（Chinese copy standard）

页面上的中文只做两件事：说清一个判断，给出支撑它的名词和数字。下面八条是评审里反复出现的措辞问题，每条都有改法；§9 是两页真实页面的前后对照，§10 是定稿清单。

`ANTI-SLOP.md` 管语气和结构（AI 腔、装饰标签、文案预算）；本文只管中文本身：动词、术语、并列、中英混排、标点、脚注。两份都要过。

## 1. 动词必须带宾语

页面短句最容易丢宾语。读者看到「发完」「写完」「分错了」，得自己猜发的是什么、写完的是什么。

| 不改 | 改成 |
|---|---|
| 37 人换辖区，0 个角色变化，1 分钟发完 | 37 人换辖区，0 个角色变化，发布只用 1 分钟 |
| 写完，10/31 22:00 发布 | 10/31 22:00 发布 |
| 分错了就回滚到 v2026.10 | 发错了就回滚到 v2026.10 |

- 「发完」「写完」这类动补结构，如果句子没有宾语，不许单独成句。`lint: copy.zh-dangling`
- 补不出宾语，说明这个动作不是重点，删掉整句（「写完」）。
- 顺手删「是……的」判断句：`每一跳带的是同一个用户身份` → `每一跳都带同一个用户身份`。

## 2. 一词一义

同一个对象在一页里叫三个名字，读者会以为是三件事。

| 不改 | 改成 |
|---|---|
| 标题「换辖区」、标签「经销商范围」、步骤「辖区表导入」、结尾「新范围」 | 全篇「辖区」；首次出现写「辖区（经销商范围）」 |

- 首次给全称（括号补一句），之后统一简称；同义词留着区分不同对象，不用来换行文。
- 定稿前搜一遍同义词表，每份 deck 选一个就锁死：`辖区 / 范围`、`角色 / 权限`、`发布 / 上线`、`token / 令牌`、`Agent / 智能体`。

## 3. 并列项要补齐、同调

四项并排时，任何一项缺主语、缺宾语，或者突然变成口语缩写，都会把读者拽出节奏。

| 不改 | 改成 |
|---|---|
| 是谁在问 / 能不能调 / 认不认人 / 能不能看 | 是不是本人 / 能不能调 / 认不认这个身份 / 能看哪一块 |

- 同一行的标签回答同一层的问题，开头词尽量一致（是不是 / 能不能 / 认不认）。
- 口语只用在动词上（拒、改、发、回滚），不用在术语上：「认不认人」「分错了」都不行。
- 并列项长度差不超过三个字（5 / 4 / 7 / 5 可以，4 / 12 不行），超了就把长项压回标签长度。

## 4. 中英混排

| 不改 | 改成 |
|---|---|
| authentik 签发 token：roles + channel / bu / region / dealer_ids | authentik 签发 JWT，claim 带 roles、channel、bu、region、dealer_ids |
| Agent Registry 由 Portal 自建 | Agent 登记表由 Portal 自建 |

- 产品名按官方写法，全篇一个写法：`agentgateway` 全小写、`Portal` 首字母大写、`JWT` 全大写。
- 中文与英文、数字之间留一个半角空格：`37 人`、`1 分钟`、`access token 有效期`。`lint: copy.unit-space`
- 首次出现给中文，之后用原文：`Agent 登记表（Agent Registry）`。
- 不要用 `+`、`/`、`：` 拼句子。列表用顿号，句子用逗号。

## 5. 标点

- 中文句子用全角标点；半角 `, ; : ( )` 只出现在纯英文片段里。
- 一句话最多一个分号，分号两边必须是并列分句，不能是「总述；解释；补充」三段式。
- 数字和中文之间留空格；范围用 `–`（`37–55`）；日期只用一种写法（`10/31` 或 `11 月`），不要同页混用。
- 不用破折号补结论（见 `ANTI-SLOP.md`）。

## 6. 脚注只说来源和口径

| 不改 | 改成 |
|---|---|
| 示例来自方案 6.6 的月度辖区调整案例，案例数字为估算值。 | 来源：方案 6.6 月度辖区调整案例；数字为估算。 |
| agentgateway 没有内置注册中心（代码与资源类型实查） | agentgateway 没有注册中心。 |

- 读者不关心你怎么查的。一句「来源：X；口径：Y」就够；删掉「示例来自 / 实查 / 本页 / 本文」。`lint: copy.zh-meta-source`
- 每份 deck 只声明一次估算口径，不要每个数字后面挂「（估算）」。

## 7. 去译腔

| 不改 | 改成 |
|---|---|
| 角色与属性的唯一写入者也是 Portal | 角色和属性也只有 Portal 能写 |
| 切换之所以便宜，是因为应用只依赖 OIDC 标准 | 切换便宜，靠的是应用只依赖 OIDC 标准 |
| 对于业务系统而言，…… | 业务系统…… |
| 进行了角色调整 | 改了角色 |

命中就改写，改写不了就删：`唯一……者`、`作为……的`、`对于……而言`、`之所以……是因为`、`综上所述`、`需要注意的是`、`进行了`。`lint: copy.zh-translationese`

## 8. 长度与节奏

- 标题一句话、一个动词。不要「X，Y」两个并列小句硬凑节奏，除非是数字排比（`37 人……，0 个……，发布只用 1 分钟`）。
- 正文 ≤ 60 字，标签 ≤ 12 字，一页只讲一个判断。
- 一个名词短语超过 12 字就拆：`登录凭证下次刷新自动拿到新角色` → `凭证下次刷新生效`。

## 9. 两页示例（before / after）

### P05 一次调用穿过四层

| 位置 | 不改 | 改成 | 为什么 |
|---|---|---|---|
| 标题 | 每层只做一个判断 | 每层只回答一个问题 | 下面四项是问句，标题说「判断」对不上 |
| 四问 | 是谁在问 / 认不认人 | 是不是本人 / 认不认这个身份 | 「认不认人」是俚语缩写，缺宾语；四项同调 |
| 副标题 | `token：roles + channel / bu / region / dealer_ids` | `JWT，claim 带 roles、channel、bu、region、dealer_ids` | 冒号套加号和斜杠，读者要拆符号 |
| 正文 | 每一跳带的是同一个用户身份；任何一跳说不清是谁，就拒绝。 | 每一跳都带同一个用户身份。说不清是谁，就拒绝。 | 「是……的」+ 分号串两句 |

## 10. 定稿五步

1. **只读标题**：能不能连成一段论证；每句有没有动词。
2. **找悬空动词**：`完 / 好 / 错 / 掉` 后面有没有宾语。
3. **统一术语**：同义词表逐个合并，一页只留一个名字。
4. **查混排**：空格、大小写、顿号，别用 `+` 和 `/`。
5. **查脚注**：只留来源和口径，删自证式说明。

跑 `python3 scripts/deck_lint.py deck.pptx`：标了 `lint:` 的条目有自动检查（`copy.zh-dangling`、`copy.zh-meta-source`、`copy.zh-translationese`、`copy.unit-space`）；没标的是一词一义、并列同调、标点、大小写，靠通读——这些恰好是最容易被自动检查漏掉的。
