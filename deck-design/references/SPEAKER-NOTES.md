# Speaker notes 标准（default on, every slide）

默认每一页都写备注，除非用户明确说不要。没有备注的 deck 在评审现场只剩朗读页面文字，这是默认要避免的状态。

`deck_lint.py` 默认把「缺备注」判成硬失败；`--no-notes` 只用于确实不需要口播的场景（例如纯附录 deck）。

## 一条备注的骨架：80–150 字

三段，按顺序写，不写小标题：

1. **结论句（1 句，20–40 字）**：用口语把标题说一遍，比标题多一个对象或动作。听众先听到判断，再听到支撑。
2. **论据（1–2 句，40–80 字）**：把页面上最关键的那个数字或机制讲成因果。数字要说出来，口径说一次。
3. **过渡（1 句，15–30 字）**：指向下一页，或者点明要听众做的判断。用内容接，不用「接下来我们看」。

示例（P10，37 人换辖区）：

> 这次只换了 37 个人的辖区，角色一个都没动。因为辖区是属性，改的是组织组，第二天登录就是新辖区。全程四步：导入 11 月辖区表、华东华南确认、管理员提交审批、次日生效，发布只用了 1 分钟。万一发错，回滚到 v2026.10；也可以只给一个人打补丁。

## 写法

- **第一人称，短句**，一口气能念完；一句里不超过两个逗号。
- **数字要念出来**，并带一次口径（「估算」「按 token 有效期」）。同一页只声明一次。
- **不念页面文字**：页面标签在备注里最多复述一次；复述整句会被 `notes.echo` 抓到。
- **不加页面没有的东西**：备注可以解释因果、举一个页面上的例子，但不引入新事实、新数字。要补就回页面或进附录。
- **一页一个判断**：讲不完说明这页该拆，不是备注该写长。
- **中英混排、术语与页面一致**：按 `ZH-COPY.md` 的写法，产品名不换大小写。

## 不要写

- 页面正文整段复制。
- 「如图所示」「本页」「接下来我们」「大家可以看到」。
- 排练指令（「这里停一下」「看向观众」）、时长标注、页码、章节名。
- 免责声明式的收尾（「以上是我的汇报」）。

## 什么时候写

页面文案定稿之后再写。文案还会改的时候先写备注，等于两遍都改。

写完整的 deck，按三页一批的节奏：每批渲染、贴 3-up 网格时，把这批三页的备注一起写掉，随批交付。

## 落盘

- **python-pptx**：`slide.notes_slide.notes_text_frame.text = "……"`。这会在包里创建 `ppt/notesSlides/notesSlideN.xml` 和 notes master（缺失时自动补）。
- **OOXML 手改**：备注在 `ppt/notesSlides/notesSlide*.xml`，编号与 `slideN.xml` **不一一对应**，按该页 `.rels` 找目标文件，改 `<a:t>`，注意转义 `& < >`。
- **Google Slides**：备注随 `.pptx` 导入/导出往返；导入后在备注面板可见。

## 检查

```bash
python3 scripts/deck_lint.py deck.pptx          # 缺备注 = 硬失败
python3 scripts/deck_lint.py deck.pptx --no-notes
```

- `notes.missing`：有页面没有备注（硬失败）。
- `notes.length`：少于 60 字或超过 220 字（警告；目标 80–150）。
- `notes.echo`：备注与页面文字有连续 25 字以上的重合（警告），多半是复制了正文。

三处都过，再做视觉检查。
